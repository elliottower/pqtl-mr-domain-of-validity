- Pre-stage note (B, what counts as unavailable): a regional or outcome file is recorded as unavailable, with the registered consequence (colocalization not run, inconclusive state), only when the source definitively does not hold it: HTTP 404 or 410, a file the source's own listing does not name (a SeqId absent from the deCODE folder listing or named there more than once; an Olink assay without exactly one tar in Synapse syn51365303; a chromosome without exactly one rsID map in syn51396727; a tar without exactly one file for the chromosome), or a GWAS Catalog accession without exactly one harmonised file. Stage B is assembled only when every planned file has a collect record and every unit a result. The same rule applies to the eQTL Catalogue queries of the splicing flag (missing only on a definitive absence). Ensembl has a narrower rule. Its only definitive absence is an HTTP 400 for which all of the following hold: the body parses as Ensembl's error JSON, an object whose single key `error` holds a string; that string is, in full, Ensembl's unknown-identifier message, the rsID followed by ` not found for human` on the variation endpoint or `No variant found with ID` followed by the quoted rsID on the VEP endpoint; the rsID it names is one that was requested; and it says nothing else, so a message about request size, malformed syntax, a backend fault or a page not found is not an absence. Every other Ensembl 400 raises as a protocol fault, and so does an Ensembl 404 or 410, because Ensembl's REST documentation gives 404 for a badly formed URL and 400 for an identifier it cannot find.
